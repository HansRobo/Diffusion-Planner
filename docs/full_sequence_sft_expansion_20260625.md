## Old SFT whitelist

The expansion is constrained by the currently used SFT lists:

```text

```

The full-sequence global lists are not used directly because they include many
other projects/areas.

## Matching key

To avoid mixing unrelated data, the whitelist key is:

```text
(split, date, session, route_id)
```

Examples:

```text
train, 2026-03-05, 10-14-20, 00000000
valid, 2026-01-15, 13-42-45, 00000000
```

For old path formats such as `xx1_real_train`, `j6_real_train`, and `xx1_psim`,
the split is normalized to `train`. For `*_valid`, it is normalized to `valid`.

## Interpretation

This is not a full replacement for the previous SFT dataset.

The full-sequence dataset currently covers only part of the old SFT route whitelist:

- train route coverage: 512 / 10,208 route keys
- valid route coverage: 4 / 15 route keys

The missing valid routes are mostly old `xx1_real_valid` sessions from 2025-06 that
are not present in the 20260623 full-sequence global lists.

## Recommended use

For temporal-consistency development:

- use the full-sequence train list above
- use the full-sequence valid list for sequence-specific validation

For strict metric comparison to the current matched baseline:

- keep the old valid list as the primary validation list, or run a matching no-DFP
  baseline on the same full-sequence train/valid lists

Do not compare a full-sequence-trained DFP run directly against the current old-data
baseline without noting the data change.
