02 · from zero

先不用懂 RL：它其实是一道驾驶考试

scene → candidates → score → learn

同一个道路场景，模型不只写一份答案，而是写出 K 份未来路线。评分器逐条检查“撞没撞、越没越界、是不是沿正确路线、是否舒适”，AWR 让高分答案获得更大的训练权重。

03 · original HDP RL

原版 HDP 的 RL：完整轨迹是 action

faithful reference

它到底优化什么？

HDP 对同一 scene 采样一组完整 plans，使用 PDM-style safety / progress / lane / comfort evaluator 排序，然后做 reward-weighted diffusion regression。目标直觉可以写成：

π_new(τ | s) ∝ π_old(τ | s) · exp(β · R(s,τ))

更新靠近旧策略，但更偏向高 reward 的整条轨迹。

为什么是组内比较？

直路和复杂路口的 raw reward 范围不同。HDP 在同一 scene 的 K 条候选内做 mean/std normalization，再变成 AWR weights；常数 reward group 没有方向，应被记录/跳过。

HDP 已证明有效的生命周期

全量/分批 rollout mining → 记录 scene/group/weights → replay buffer 混合旧样本 → 周期性 refresh 发现新错误 → EMA checkpoint 继续采样。我们复现的是这个 lifecycle；当前训练目标仍是普通 DP 的 plain MSE。

吸收 HDP

AWR lifecycle

  • 同 scene 采样 K 条完整轨迹，禁止 guidance 伪造候选
  • reward-weighted regression + group normalization
  • disk replay、每 10 个 epoch refresh、EMA 0.999
  • HDP trajectory augmentation 作为正式探索分支；所有候选仍由同一 reward 打分

为什么 plain MSE

HDP 的 hybrid waypoint/velocity head 属于 HDP 架构；普通 DP 没有这些输出，不能把论文 loss 名称硬套进来。

为什么 replay

全量 4.5M scenes 不应只在一个 streaming pass 后丢掉；replay 让旧修复继续约束模型，减少遗忘。

为什么不先 PPO

当前是 logged-neighbor replay、trajectory-level reward；AWR 更短、更稳，也更忠实于 HDP 已验证路径。

06 · metric guide

指标不是一堆数字：它们分别在防什么？

hard gate first · quality second
第一层 · 不可补偿

Safety / hard constraints

  • Collision / OBB clearance：ego 与邻车 oriented boxes 是否重叠，signed clearance 是否穿过 0。
  • Road-border：ego footprint 是否越过道路几何边界。
  • Red-light：激活的 stop line 是否被跨越。
  • Kinematic：yaw-rate / curvature / acceleration 是否违反可行性。

原则：progress 不能用来抵消安全硬错。

第二层 · 风险余量

TTC / THW / follow

  • TTC：按当前接近速度，距离可能碰撞还有多久。
  • THW：与前车的时间间隔；停止 leader 不应被 progress 催着追上。
  • Follow：有 leader 时才激活，不能把没有前车的 scene 惩罚成“不会跟车”。
  • Coverage：K 条里有几条真的安全；没有 safe branch 就不能声称 AWR 能修。
第三层 · 行为质量

Progress / lane / comfort

  • Route progress：沿 route 的前进，不是任意向前或直线 shortcut。
  • Lane likeness：正常车道保持要好；expert 明确变道时必须 mask，不能把合法变道当错误。
  • Comfort：平滑、低 jerk、可执行。
  • ADE/FDE：只说明像不像 logged expert，不是安全证明。
报告每个指标都必须回答：触发条件是什么？在什么场景应该激活？怎样画出 bbox/轨迹证明它？如果指标没有触发或 candidate coverage 为 0，就报告为“未覆盖”，不把它包装成成功。

09 · scene semantics

车道保持不是“永远不许变道”

lane is conditional · K=16 diagnostic

Stopped leader：如果 leader 停着，progress 不能催 ego tailgate；先看 OBB clearance/THW/follow。没有可用 leader 时，follow 应该 neutral，而不是惩罚。

Tight right turn：route centerline 和 border 是几何约束；合法转弯的 lateral movement 不能被简单的“lane crossing”判错，真正要查的是 route likeness、border 和 kinematic feasibility。

lane mask

expert 明确发生 lane change / turn 时，关闭保持原 lane 的惩罚，保留 route 和 border。

progress mode

moving scene 看 route progress；red light / stopped leader 看 stationary distance 与 safety gate。

hard safety

无论是否变道，collision、road-border、kinematic violation 都不能被行为分数抵消。

每个指标都要按场景语义激活，避免“lane 一刀切” · amber=stopped, red=hard violation10 / 15

11 · absorb R2LPL

R2LPL 不替代 AWR：它修复 AWR 无法覆盖的 override scene

rollout–retrieval lifelong policy learning
R2LPL 核心

它解决什么？

当前模型在 semi-closed-loop 复现真实 drive，发现 collision / border violation 或 expert disagreement；对错误 credit window 检索/生成一个可行 repair target，再 supervised train，随后用新 checkpoint re-mine。

如何接到我们的主算法

普通 scene：AWR 用模型自身 K samples 做全量 post-training。override scene：当 safe-candidate coverage 低、或 closed-loop disagreement 持续出现时，进入 R2LPL repair lane，修复 pair 进入 bounded replay memory。

Provenance rule：open-loop collision、downstream closed-loop label、expert disagreement 必须分开记录；不能把所有 moving-collision window 都写成“模型在 credit frame 撞了”。
R2LPL paper/code is a targeted coverage repair mechanism, not a reason to abandon AWR12 / 15
12 · strongest proposal

最终提案：大规模 AWR 主干 + R2LPL 纠错支路

two-lane training system
LANE A · broad post-training

Original DP AWR

  1. 全量 filtered T4 scene，旧数据 neighbor future 按 +1。
  2. 每 scene K=10 unguided DP plans；不注入 anchor guidance。
  3. Safety gate → risk margin → route/progress/comfort；组内 normalize。
  4. plain diffusion MSE + disk replay + EMA；每 10 epoch refresh。
  5. 每轮输出 candidate coverage、ESS、reward concentration 和分层 metrics。
LANE B · override repair

R2LPL retrieval / repair

  1. semi-closed-loop reproduction：ego closed-loop，邻车按记录 replay。
  2. 区分 realized violation 与 open-loop expert disagreement。
  3. 取 violation 前 credit window；K candidates 规则过滤，必要时加入 GT-informed morph。
  4. 只保留 rule-feasible repair；无可行 target 就丢弃并计数。
  5. repair pairs 进入 bounded replay；新 checkpoint 继续 re-mine。
共享原则：同一个 OBB-aware evaluator、同一个数据 provenance、同一个 promotion gate。 AWR 负责“整体分布向更好候选移动”，R2LPL 负责“候选集合根本没有正确答案时补答案”。
proposal: preserve scalability, add targeted coverage recovery13 / 15

hard safety guard

collision、kinematic、road-border、red-light violation 和 zero-clearance tail 不能显著变差；安全指标优先级高于 reward gain。

behavior guard

moving/stationary progress 分开；lane-change mask 正确；follow/THW、comfort、ADE/FDE 不允许用冻结或漂移换来安全表面提升。

distribution guard

按 red-light、moving conflict、stopped leader、turn、lane-change、hard/normal slices 分层；至少一个更交互的 replay/closed-loop branch 复核。

最终规则：只在固定 valid paired evaluation、全量分层 evaluation 和 provenance 检查都通过后，才把单一 AWR checkpoint 交给实车；否则保留原 DP，并用失败 slice 进入 R2LPL repair。
